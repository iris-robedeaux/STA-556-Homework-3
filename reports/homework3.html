  1. \(X\) and \(y\) must have the same number of rows, as they match the total number of observations in the original data set. \(X\) and \(\beta\) have compatible inner dimensions to multiply, producing a single column. This single column is the predicted value, matching the single column in the \(y\) matrix.

  2. The intercept column must be included, otherwise the prediction line would go through the origin. The column is all ones, but is necessary. It results in the intercept \(B_0\) being added to every prediction, creating accurate estimates.

  3. Standardizing allows you to compare the predictors. Since they are all on different scales, directly comparing their coefficients would be meaningless. Once they are all standardized, with a mean of 0 and standard deviation of 1, then the comparison between coefficients can be made accurately.

  4. Broadcasting allows the operation to be done automatically. A loop would require messing with indices and possibly an error. Broadcasting means that the elements are already matched with each column, creating a smooth command.

fitted = X @ beta_hat
residuals = y - fitted

rmse = np.sqrt(
    np.mean(
        residuals ** 2
    )
)

print("residual mean:", residuals.mean())
print("RMSE:", rmse)
residual mean: 5.24708481792074e-15
RMSE: 28.818978213959117

  1. The \(X @ {beta}_{hat}\) produces matrix multiplication between the X matrix and the coefficients. This produces the predicted values for each of the given predictor combinations given within the data set.

  2. The residual mean is near zero because of how residuals are created. The linear prediction is built on reducing the value of the residuals, and by nature, the sum of them must be zero. Since the sum of residuals of zero, the average will be too. The actual values might be off a bit in the output due to floating point rounding.

  3. RMSE is the estimated size of the error between the prediction and the actual values. It averages the square of each of the errors (removing the negatives), which gives the absolute average distance between the observed values and the prediction line. It gives the average size error for the data.

  4. \(X @ {beta}_{hat}\) performs the proper matrix dot product in order to find the actual predictions. \(X * beta_hat\) would provide an element-wise broadcast across the columns. It would do the correct operation of multiplying each coefficient for each of the predictors, however it wouldn’t sum them. The resulting matrix would still have 4 columns, instead of just the one for the prediction.

  1. \(Q @ R \approx X\) verifies that the QR factorization is correct. It ensures that by multiplying the factors together, you recover the design matrix.

  2. \(Q^T @ Q \approx I\) verifies that the columns of Q are orthognoal. This is a defining property of Q, so it’s a necessary check.

  3. The singular values measure how much \(X\) stretches in space into that direction. Smaller values mean the column holds little independent information that cannot be known from the other columns.

  4. A large condition number suggest numerical instability, as small changes in one value can heavily affect the coefficients. Smaller values are better.

  5. Yes, the raw condition number is about 10733, but the standardized condition number is 2.7.

  6. The original condition number is based on unscaled predictors. The condition values reflect the differences between the small and large values, which are inflated because they are on different scales. Standardizing the predictors puts them on the same scale, making the condition value much smaller.

  7. The standardized \(X\) has a small condition number, about 3, and the smallest singular value is 5.7. Both of these indicate that the model has very little near-redundancy. There is little evidence that any of the predictors are correlated.

Part 5: Reproducibility and Numerical-Computing Reflection

Clean execution matters for a computational report to ensure that anyone reviewing your work can trust it. If the execution isn’t clear, any people looking at your code could either stop looking at it or hesitate to run the unknown code. Further, running the code top-to-bottom allows the results come from the code itself. It verifies that results needed in each succeeding line follows from the previous executions. Reusable code shouldn’t rely on the notebook state by definition. In order to be reproducible, the code must create any necessary variables or objects within the code or use provided data files. In addition, it provides that variables are defined before they are used. The lstsq command is more efficient than the manual calculation because it doesn’t rely on inverses. Since it works with X directly through factorizations, it can skip the computationally heavy inverse calculation. It’s also necessary for accuracy. Using matrix computations could break down the inverse when predictors are nearly redundant. The allclose command is necessary since the matrix operations in commands like \(Q @ R\) introduce floating point error. While any check for perfect equality will very likely result in a False output, allclose checks if the values are close within a given error amount. The condition number comparison indicates how numerical diagnosis can have standards for the baselines, but comparison is the most important part. It also allowed me to understand how scale of predictors has a large impact on the condition number. A large number could be indicative of unscaled predictors, instead of only redundant predictors. Comparing the before and after of an analysis step allows the improvements to be clearer.
